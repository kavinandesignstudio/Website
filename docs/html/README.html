2. Preview on your computer

Easiest: double-click OPEN WEBSITE.html in this folder. It opens the offline copy (offline/index.html), which works straight from your drive or a USB stick, no installs needed. (Fonts and maps load when you're online; everything else works offline.)

Full preview (exactly like the live site): double-click Preview Website.bat. It rebuilds the site and opens http://localhost:8000. Keep the black window open while browsing. Or run it yourself:

python build.py --serve

After editing content, refresh the offline copy with:

python build.py --offline

Why not public/index.html? That folder is the version for the web server: its links start with /, which on a local drive points to the root of D:. That's why pages looked broken when opened directly. Use OPEN WEBSITE.html or the .bat file instead.

3. Go live — GitHub Pages + Zoho Domains

Follow docs/HOSTING-GITHUB-ZOHO.md, which covers it step by step:

  1. Put this website folder on GitHub with GitHub Desktop (repository name USERNAME.github.io, public).
  2. Settings → Pages → Source: GitHub Actions. The included workflow builds and publishes the site.
  3. In Zoho Domains → DNS Management add 4 A records for @ (185.199.108–111.153) and a CNAME

www → USERNAME.github.io. Leave your Zoho Mail records (MX, SPF, DKIM) untouched.

  1. Settings → Pages → custom domain www.kavinandesignstudio.com → Enforce HTTPS.
  2. Get a free Web3Forms key and paste it into content/site.json → form → access_key so the forms email you.
  3. Optional: add the ANTHROPIC_API_KEY secret so Claude writes articles from your updates.

From then on: edit files → commit & push in GitHub Desktop → live in about 2 minutes. Every morning at 06:00 IST the site also rebuilds itself, releasing scheduled posts.

Other hosts: the site also runs on Netlify (netlify.toml included; set form.provider to "netlify") or any cPanel host (upload public/ into public_html; .htaccess included).

Add a journal post by hand

Create content/journal/2026-11-20-my-post.md:

---
title: Your headline here
date: 2026-11-20
description: One or two sentences (130–160 characters) shown in Google results.
tags: Homeowners guide, Renovation
cover: s-gan-villa/sg_c2
project: s-gan-villa
---
Your article in Markdown. Use ## for headings, - for bullet lists, > for a pull quote,
**bold**, and [links](/contact.html).
  • Schedule it: give it a future date. It stays hidden and goes live automatically on that morning.
  • Hide it: add draft: true.
  • cover is any image key from assets/img/manifest.json (folder/name without the size).

Six articles are already scheduled to publish every two weeks until January 2027.

Let the studio write for you (automatic)

Drop a 2–3 line note into content/updates/ whenever something happens on a project — see content/updates/README.md. Every morning the automation turns new notes into a full article plus 1–3 new FAQs. Every Monday it also writes one practical guide from content/topics.txt. New FAQs show a green New badge for three weeks.

Add a new project

  1. Keep the project's final images in its own folder, e.g. D:\KDS\Mr. XYZ Residence\Renders\.
  2. Open tools/optimize_images.py and add a line to SOURCES, pointing at the files:

``python "xyz-residence": [("xyz_1", "Mr. XYZ Residence/Renders/1.jpg"), ("xyz_2", "Mr. XYZ Residence/Renders/2.jpg")], ` Then run pip install pillow numpy (once) and python tools/optimize_images.py`.

  1. Copy an existing project block in content/projects.json, change the slug, text and image keys

(xyz-residence/xyz_1 …), and rebuild. The project page, sitemap, listings and film strip update themselves.

  1. Optional pencil sketch: add the image key (e.g. "xyz-residence/xyz_1") to SKETCHES in

tools/make_sketches.py and run python tools/make_sketches.py. The project page then gets a drag-to-compare "Sketch → Render" slider automatically.

  1. Add a note in content/updates/ so the journal announces it.

Illustrations and animations

  • The hand-drawn line illustrations (architecture, interiors, landscape, PMC, design + build, courtyard

and the five process stages) live in illustrations.py. They are plain SVG strokes, so they follow light/dark mode and draw themselves as visitors scroll.

  • Motion respects visitors who switch on "reduce motion" on their phone or computer: everything still

shows, just without animation.

6. Technical notes

  • Pure static HTML/CSS/JS — no WordPress, no database, nothing to hack or update. Loads fast on 4G.
  • Images are WebP in 640 / 1280 / 1920 px with srcset, lazy loading and fixed dimensions (no layout jump).
  • Light/dark mode follows the visitor's phone/computer setting and remembers their choice.
  • Accessible: skip link, keyboard-navigable menu, lightbox and FAQs, visible focus, reduced-motion support.
  • Structured data (JSON-LD): ProfessionalService + GeneralContractor (both offices), WebSite, BreadcrumbList,

Service, CreativeWork (projects), BlogPosting, FAQPage, Person.

  • Fonts: Outfit (headings, geometric like the logo wordmark) + DM Sans (text) from Google Fonts.
  • Colours come from the logo: orange #F26122 and forest green #126249. Dark mode is deep forest green, not black.
